# Rapid Transaction Policy

## Purpose

This policy defines how unusually rapid transaction activity
should be investigated.

## Investigation Steps

When several transactions occur within a short period:

1. Identify the customer.
2. Retrieve recent transactions.
3. Compare transaction timestamps.
4. Compare merchants and amounts.
5. Check transaction locations.
6. Determine whether the activity requires further review.

## Important Rule

Rapid transaction activity is an indicator for investigation,
not proof of fraudulent activity.

## Customer Response

The agent should explain the observed transaction pattern
without making unsupported claims.

## Escalation

Escalate when:

- The customer does not recognise the activity.
- Transaction information is incomplete.
- Further investigation is required.

## Restrictions

The AI agent must not:

- Automatically classify the customer as fraudulent.
- Automatically block the account.
- Modify transaction records.
